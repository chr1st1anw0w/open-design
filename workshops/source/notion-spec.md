## 0. 提示詞使用說明｜How to Use This Prompt

### 0.1 適用情境

- 將此頁面整段貼入支援長上下文之模型，即可一次生成完整簡報草稿。
- 亦可分章節餵入，採 `!loop` 模式逐章迭代修正。

### 0.2 全域設計變數 (Global Variables)

| 變數 | 建議值 | 說明 |
| --- | --- | --- |
| `AUDIENCE` | 瑄燁團隊 10 人（3 技術、2 決策、5 商學） | 大多聽眾接觸過ai，但不熟悉，目標是讓聽眾了解到AI基礎知識跟概念 |
| `DURATION` | 120 分鐘 | 講解 30% + 示範 40% + 實操 20% + Q&A 10% |
| `TONE` | 專業客觀第三人稱，避免主觀「我覺得」，強化SEO及HOOK語氣以便吸引聽眾注意力 | 對應長期指令之語氣規範 |
| `LANGUAGE` | 繁體中文為主，技術詞中英對照 | API (應用程式介面)、Token (語意單元) 等首次出現註解 |
| `SLIDE_RATIO` | 16:9 | 建議解析度 1920×1080 |
| `DESIGN_SYSTEM` | 請參考此[awesome-design-md](https://www.notion.so/awesome-design-md-4f0261146a3c47fdb9054140ea39b978?pvs=21) 並詢問及建議 | 對比強烈，便於遠端投影辨識 |
| `FONT` | 標題：Noto Sans TC Bold / 內文：Noto Sans TC Regular / 程式碼：JetBrains Mono | 跨平台可用 |

### 0.3 視覺呈現語法約定 (Visual DSL)

```yaml
  left_zone:

```

> 

> 
> 

> 「真正的 AI Workflow 應該具備三個特徵：**可重跑（Reproducible）、可追蹤（Traceable）、可交付（Deliverable）**。今天接下來的所有內容，都圍繞這三個特徵展開。」

### 2.4 P4｜文件工程基礎：傳統格式的五大問題

#### 標題層級

- **H1**：為什麼 Word 檔可能是 AI 協作效率最低的格式？
- **H2**：傳統文件的五大問題
- **H3**：不易切分 / 不易追版 / 不易給上下文 / 不易自動化 / 易幻覺

#### 演講稿（10:00 – 18:00）

> 「DOCX、PPTX、PDF 都是『給人看的格式』，不是『給機器讀的格式』。當你把一份 50 頁的 Word 丟給 AI，它要做的第一件事，其實是先把這份 Word 拆掉、再重組成自己看得懂的結構。這個過程不僅耗 Token，更會在拆解時遺失語意。」
> 

#### 視覺呈現建議

- **Layout**：`grid-2x2`，四個象限分別放四個問題的視覺隱喻。
- **對比圖**：核心對比 — 左邊「DOCX 內部 XML 樹狀展開（密密麻麻、紅色標記亂碼）」 vs 右邊「Markdown 純文字（乾淨、藍色標記層級）」。
- **照片配置**：可加入辦公室桌面照——左邊「散落的紙本與隨身碟」、右邊「整齊的 Git 提交歷史截圖」。
- **螢幕錄影建議**：**強烈建議放一段 20 秒螢幕錄影**——示範用 VS Code 開啟一份 .docx 的 raw XML，與同份內容轉成 .md 後的對比，視覺衝擊極大。
- **實體操作**：無。

### 2.5 P5｜格式適配矩陣

#### 標題層級

- **H1**：選對格式，AI 才跑得動
- **H2**：8 種格式 × 3 種角色（輸入 / 中間 / 交付）
- **H3**：DOCX・PPTX・PDF・圖片・Markdown・JSON・CSV・YAML

#### 演講稿（18:00 – 25:00）

> 「重點不是『哪個格式最好』，而是『哪個格式最適合哪個階段』。DOCX 是好的交付格式，但是糟糕的中間格式；Markdown 是優秀的中間格式，但通常不是最終交付格式。**先區分階段，再選格式**，是文件工程的第一原則。」
> 

#### 視覺呈現建議

- **Layout**：`full-bleed` 表格，欄列以顏色深淺強化「適 / 不適」。
- **對比圖**：在表格下方加一條漸層流程條：`輸入 → 中間 → 交付`，並標示每階段建議的 Top 3 格式。
- **照片配置**：不需照片，純資訊圖表頁。
- **螢幕錄影**：無。
- **實體操作**：可發放紙本「格式選擇 Cheat Sheet」（A4 雙面），現場讓學員圈出自己公司現用格式。

### 2.6 P6｜AI 文件化標準流程

#### 標題層級

- **H1**：原始檔案 → Markdown → AI 處理 → 重組輸出
- **H2**：五階段標準流程
- **H3**：轉換 / 切分 / AI 編修 / 人工審核 / 重組匯出

#### 演講稿（25:00 – 32:00）

> 「請記住這條主動脈：**檔案進來不是直接給 AI，而是先轉成 Markdown 小檔，分章節給 AI 處理，再由人審核，最後組裝回 PPT 或 Word 交付**。這條流程不只是技術建議，它直接決定你公司能不能把 AI 的成本壓在合理範圍。」
> 

#### 視覺呈現建議

- **Layout**：`full-bleed` Mermaid 流程圖。
- **對比圖**：上半部「傳統作法：DOCX → AI → DOCX（紅色 X）」 vs 下半部「建議作法：DOCX → MD → AI → MD → DOCX（綠色 ✓）」。
- **照片配置**：流程節點旁可加上小型 icon（檔案、齒輪、人眼、輸出箱），不放真實照片。
- **螢幕錄影建議**：**建議錄製 60 秒示範**——MarkItDown CLI 將一份 PPTX 一鍵轉為 MD，再用 Pandoc 把 MD 轉回 DOCX，全程一鏡到底。
- **實體操作**：講者可帶一支 USB，現場示範把學員提供的小檔案做一次完整轉換。

### 2.7 P7｜模型選型矩陣

#### 標題層級

- **H1**：為什麼最強的模型，常常是最浪費成本的選擇？
- **H2**：七大情境的模型對照
- **H3**：分類 / 推理 / Vision / RAG / Coding / 表格 / 會議

#### 演講稿（32:00 – 42:00）

> 「企業導入 AI 的最大隱形成本，不是訂閱費，是**用錯模型**。用 GPT-5 級別的模型去做檔名批改，就像請米其林主廚煎荷包蛋——做得到，但完全不划算。」
> 

#### 視覺呈現建議

- **Layout**：`grid-2x2`，四象限分別為「便宜 / 高階 / Vision / RAG」。
- **對比圖**：橫軸「任務複雜度」、縱軸「成本」，散布點呈現不同模型在不同任務的 ROI 位置。
- **照片配置**：左下角配「計算機 + 帳單」實物照，右上角配「複雜決策樹白板」照，強化「成本 vs 推理」的對比。
- **螢幕錄影建議**：可錄一段對比實驗——同一份 30 頁 PDF，分別用便宜模型 + 拆分 vs 高階模型 + 整份塞入，呈現兩者 Token 使用量與時間。
- **實體操作**：發 6 張任務卡，請各組舉牌選模型。
